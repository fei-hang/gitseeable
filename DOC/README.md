## 1. 首页：选择仓库

打开应用后，首先看到的是仓库选择页面。应用会自动恢复上一次访问的目录，也可以通过下面几种方式定位到其他目录。

### 手动输入路径

在页面顶部的输入框中，可以手动粘贴或输入目录路径（例如 `D:\projects`），然后点击 **前往** 按钮定位到该目录；点击 **盘符列表** 按钮则会列出当前系统的驱动器（如 C:、D:）。

### 浏览本地目录

在目录列表中点击文件夹即可进入下一层，点击 **⬆ 上级目录** 返回上一层。

### 打开目录并扫描仓库

确认当前路径后，点击页面中部的 **打开目录** 按钮。应用会以该目录为根，**递归扫描其中的所有 Git 仓库**：

- **最多向下 3 层**（当前选中的目录算第 0 层）
- **命中即停**：某个目录里一旦发现 `.git`，就把它记为一个仓库，不再继续往它的子目录里查找
- 自动跳过 `node_modules`、`dist`、`build`、`target`、`.gradle`、`__pycache__`、`.venv` 等体积巨大的目录，避免扫描耗时
- 保护上限：最多扫描 2000 个目录、最多返回 100 个仓库，超出时结果会被截断

扫描完成后会**默认进入第一个仓库**。如果一个仓库也没找到，页面会提示「该目录下没有找到 Git 仓库（最多递归 3 层）」。

![目录选择页面](04-directory-select.png)

### 多仓库切换

进入分析界面后，顶部导航栏左侧会出现一个仓库下拉框，列出本次扫描到的所有仓库，显示的是**相对于扫描根目录的相对路径**（根目录本身显示为仓库名）。选择另一个仓库即可切换；切换过程中下拉框会被禁用并显示「加载中…」，同时提交历史、本地修改、分支比较、冲突等数据会针对新仓库全部重新加载。

### 多标签页支持

每个浏览器标签页可以独立选择不同的仓库目录。选择的目录路径会记录在 URL 中（例如 `?dir=D%3A%5Cprojects%5Cmy-repo`），因此刷新页面或在新标签页中打开同一个链接，都会恢复到对应的仓库。不同标签页之间互不影响。

## 2. 主界面布局

进入仓库分析页面后，整个界面分为几个区域：

### 顶部导航栏

- **重选目录**（左上角）：返回仓库选择页面
- **仓库切换下拉**：本次扫描到的仓库列表，选择即切换（详见第 1 节）
- **仓库路径**：显示当前正在分析的仓库完整路径
- **标签页切换**：**提交历史**、**本地修改**，以及按需出现的 **分支比较**、**冲突**
- **刷新按钮**：🔄 手动重新加载当前数据
- **拉取策略滑块**：**变基 / 合并** 二选一，决定与远程有分歧时如何拉取（详见第 4 节）
- **语言切换**：中 / EN，点击切换界面语言
- **主题切换**：🌙 / ☀️，点击切换深色/浅色模式

### 左侧面板：分支列表

左侧显示一个可拖拽调整宽度的面板，包含：

- **本地分支**：当前仓库的所有本地分支
- **远程分支**：远程仓库的分支（如 origin/main）

两个分组标题后面会显示分支数量。当前所在的分支用实心圆 **●** 标记，其他分支为空心圆 **○**；分支名后面的 **▲ / ▼** 表示相对远程「可推送 / 可拉取」的提交数（悬停可以看到具体数量）。分支较多时默认只显示前 10 个，点击分组标题即可展开全部。本地分支分组标题右侧还有一个 **↻** 按钮，可以一键从远程拉取所有分支的更新。

在分支上 **单击** 选中该分支、**双击** 只看该分支的提交历史、**右键** 打开操作菜单（见下方「分支上下文菜单」）。面板右侧有一个拖拽手柄，可以左右拖动调整面板宽度。

### 右侧主内容区

根据当前选中的标签页，显示不同的内容。

![主界面概览](01-main-overview.png)

## 3. 提交历史

提交历史标签页按时间倒序显示仓库的所有提交记录。

### 提交列表

每条提交记录显示：

- **提交信息**：提交的说明文字（commit message）
- **提交哈希**：简短的提交 ID（如 `d5bf344`）
- **作者**：提交者的名称
- **日期**：提交的日期（如 `2026-06-14`）

鼠标悬停时整行会高亮；点击行会展开本次提交的文件列表；右键则打开提交操作菜单（见下方「提交右键菜单」）。

### 查看文件变更

点击任意提交记录，该行会展开，显示此次提交中所有变更的文件列表。文件列表包含：

- 文件名和路径
- 文件变更类型（新增、修改、删除）

### 查看文件差异

在展开的文件列表中点击任意文件，主内容区会显示该文件的详细差异对比（diff）：

- **逐行对比**：左侧显示原文件，右侧显示修改后的文件
- **增减标记**：绿色背景表示新增的行，红色背景表示删除的行
- **行号显示**：每行前显示对应的行号
- **对比形式**：提交详情里的文件差异是整块的「上下」形式；「本地修改」页则是「原始文件 / 修改后的文件」左右分栏形式

### 分页控制

页面底部提供分页功能：

- **每页数量**：下拉选择每页显示的提交数（10 / 20 / 50 / 100 / 200 条）
- **翻页按钮**：上一页 / 下一页
- **页码跳转**：输入页码数字，点击 **跳转** 按钮直接跳转到指定页
- **当前页信息**：显示当前页码和总页数（如 `1 / 2`）

### 未推送提交标记

当选中某个分支查看提交历史时，尚未推送到远程仓库的提交记录右侧会显示一个蓝色的 **↑** 箭头标记，方便区分哪些提交已经推送、哪些还在本地等待推送。该标记只在筛选单个分支时显示，查看全部分支时不会出现。

### 提交右键菜单

在提交列表中，右键点击任意一条提交记录，会弹出上下文菜单，提供以下操作：

| 操作 | 说明 |
|------|------|
| **优选此提交** | 将此次提交的变更应用到当前分支（`git cherry-pick`）。如果该提交本来就**已经在当前分支上**，则此选项不可用。 |
| **还原此提交** | 创建一个新提交来撤销此次提交的变更（`git revert`）。 |
| **重置到此 commit** | 将当前分支的 HEAD 重置到此提交（`git reset --hard`）。**注意：此操作会丢弃该提交之后的所有变更。** |
| **删除此提交** | 通过重写历史把此提交从分支上去掉（`git rebase --onto`）。根提交（没有父提交）不可用。 |
| **修改提交信息** | 重写这条提交的 message。会改写该提交**以及它之后的所有提交**（hash 都会变），因此如果该分支已经推送到远程，之后需要**强制推送**才能同步。 |

「修改提交信息」有两个前提，不满足时该选项不可用：

- 该提交必须在**当前分支**上（否则算不出要重写的区间）
- **合并提交暂不支持**（有两个父提交，改写语义不稳定）

另外执行前要求**工作区是干净的** —— 否则未提交的改动会被一并写进提交里。操作过程若产生冲突，会进入冲突解决流程。

操作成功后，提交历史会自动刷新。如果产生冲突（如 cherry-pick 或 revert），会显示错误信息。

重置操作会弹出确认对话框（支持"之后不再询问"选项），确认后执行 `git reset --hard`。

### 分支筛选

双击左侧面板中的某个分支名称，提交历史将自动筛选，只显示该分支的提交记录。此时顶部导航栏会出现该分支的标签，点击标签上的 × 即可恢复显示全部分支。

## 4. 分支管理

### 查看分支列表

左侧面板把分支分成 **本地分支** 和 **远程分支** 两个分组，分组标题后面是分支数量。当前所在的分支用实心圆 **●** 标记，其余为空心圆 **○**；分支名后的 **▲ / ▼** 是相对远程「可推送 / 可拉取」的提交数。分支超过 10 个时只显示前 10 个，点击分组标题可展开全部。

在分支上单击选中、双击筛选该分支的提交历史、右键打开操作菜单。

### 分支上下文菜单

在任意分支上右键点击，会弹出一个上下文菜单，提供以下操作（菜单文字会带上实际分支名）：

| 操作 | 说明 |
|------|------|
| **迁出 `<分支>` 分支** | 切换到选中的分支。如果该分支是远程分支（如 origin/feature），会自动创建本地跟踪分支。 |
| **从 `<分支>` 分支新建分支** | 基于选中的分支创建一个新分支，需要输入新分支名称。 |
| **将 `<分支>` 合并到 `<当前分支>`** | 把选中的分支合并到当前所在分支。如果产生冲突，会进入冲突解决流程。 |
| **将 `<当前分支>` 变基到 `<分支>`** | 把当前分支的提交重新应用到选中的分支之上。如果产生冲突，同样会进入冲突解决流程。 |
| **`<分支>` 分支与 `<当前分支>` 比较** | 打开「分支比较」标签页，对比两个分支的提交差异。 |
| **更新** | 从远程拉取选中分支的最新提交（见下方「拉取策略」）。 |
| **推送** | 将选中的分支推送到远程仓库。 |
| **重命名** | 修改选中的本地分支的名称。 |
| **删除** | 删除选中的本地分支。删除前会弹出确认对话框；如果分支有未合并的提交，会提示强制删除（`git branch -D`）。 |

其中 **迁出**、**合并**、**变基**、**删除** 这四项在**当前所在分支**上不会出现（对自己的分支做这些操作没有意义），**匹配到的分支名会直接显示在菜单文字里**。

### 拉取策略（变基 / 合并）

顶部导航栏的 **变基 / 合并** 滑块决定「本地与远程有分歧」时如何拉取：

| 策略 | 行为 |
|------|------|
| **变基**（默认） | 把本地提交「搬」到远程最新提交之上，历史保持一条直线，不产生合并提交 |
| **合并** | 产生一个合并提交，保留两条分支的真实历史 |

点击滑块上的文字即可切换，选择会**自动保存**，下次打开应用仍然生效。

需要注意两点：

- **能够快进时一律快进**（不产生合并提交），与选择的策略无关 —— 策略只在本地和远程真正「有分歧」时才起作用。
- 策略**只对当前所在的分支生效**。拉取非当前分支时，由于合并无法在不切换工作区的前提下作用于其他分支，此时统一走变基。

拉取过程中产生冲突时，会进入冲突解决流程。

### 远程分支管理

远程分支（显示为 `origin/xxx`）和本地分支共用同一套右键菜单：

- **迁出**：会基于该远程分支自动创建一个本地跟踪分支并切换过去
- **更新**：从远程拉取该分支的最新提交
- **重命名 / 删除**：这两个操作针对的是**本地分支**，请在本地分支上使用

远程分支本身位于远端仓库，重命名或删除需要在远程仓库上操作。

### 分支比较

在任意分支上右键，选择 **「`<分支>` 分支与 `<当前分支>` 比较」**，界面会切到 **分支比较** 标签页：

- 左右两栏分别列出两个分支各自独有的提交（ahead / behind），并标注提交数量
- 点击任意一条提交，右侧会显示该提交的完整 diff（增删行以绿 / 红底色标出）

## 5. 本地修改

点击 **本地修改** 标签页，进入工作区变更管理界面。

### 界面布局

「本地修改」页分为左右两部分：

- **左侧栏**：顶部是提交说明输入框与提交按钮，下方是变更文件列表（分为「已暂存」和「未暂存」两个分区）
- **右侧**：当前选中文件的差异对比视图
- 左右之间有一条可拖拽的分隔线，可以调整左侧栏的宽度

### 变更文件列表

文件按状态分为两个分区，每个分区标题都会显示数量（如「已暂存 (2)」）：

- **已暂存**（Staged）：已经 `git add` 进暂存区的变更
- **未暂存**（Unstaged）：尚未暂存的工作区改动，以及**未跟踪**（新）文件

每个文件项左侧是复选框，右侧显示文件名，文件名前有一个状态标记：**A**（新增）、**M**（修改）、**D**（删除）、**R**（重命名）。

> 同一个文件**不会**同时出现在两个分区里。如果一个文件被暂存之后又在工作区改动过（Git 中显示为 `MM` / `AM`），它只出现在「已暂存」分区中，并带有一个 **工作区有更新** 的角标。

### 分区操作

每个分区的标题栏都有一个**全选**复选框，右侧是针对该分区已勾选项的批量操作按钮：

| 分区 | 按钮 | 说明 |
|------|------|------|
| 已暂存 | **取消暂存** | 把选中的文件移出暂存区，改动回到「未暂存」 |
| 未暂存 | **暂存** | 把选中的文件加入暂存区，准备提交 |
| 未暂存 | **回退** | 撤销选中文件的修改，恢复到最近一次提交的状态。**未跟踪的新文件会被直接删除**（没有历史版本可恢复），此操作不可撤销 |

批量操作前会弹出确认对话框；回退时若选择中包含未跟踪的新文件，会提示「N 个文件将被回退，M 个未追踪的文件将被直接删除」。

### 查看文件差异

点击文件列表中的任意文件，右侧会显示该文件的差异对比视图：

- **原文件 vs 修改后文件**：左右分栏对比
- **逐行高亮**：绿色表示新增行，红色表示删除行
- **行号位置**：两栏的行号都紧贴中间的分隔线 —— 原始文件的行号显示在该栏的**右端**，修改后的行号显示在右栏的左端，因此两组行号是并排的，方便逐行对照
- **长行自动换行**：内容过长时在**各自栏内换行**（保留缩进与连续空格），不会横向溢出到另一栏；行高按实际换行后的高度动态计算
- **可拖拽分隔线**：左右两栏之间的分隔线可以左右拖动，调整两栏的宽度比例
- **暂存后又改过的文件**：如果该文件带「工作区有更新」角标，差异视图显示的是**工作区的最新内容**（而不是 `git add` 那一刻的快照），此时页头会额外标注「含工作区最新改动」
- **大文件支持**：采用虚拟滚动技术，即使是非常大的文件也能流畅展示差异

#### 完整上下文与折叠

差异视图默认展示文件的**完整内容**，方便了解改动所处的上下文：

- **新增 / 未跟踪文件**：由于这类文件在 Git 中尚无历史版本，整份文件会作为新增行（绿色）完整显示，行号与文件真实行号一致
- **连续未修改内容折叠**：当连续 **4 行及以上** 的内容未发生修改时，会被折叠为一条带波浪线的条带，条带左侧标注「N 行未修改，点击展开」；点击条带即可展开显示这些行，此时原条带位置会出现一条细的「收起 N 行未修改内容」横条（同样位于左侧），点击该横条即可重新折叠。少于 4 行的连续未修改内容会直接平铺显示，不做折叠
- **超大文件降级**：为避免超长文件拖慢渲染，单个文件最多展示约 5000 行；超过此上限时自动降级为「仅显示改动块及其前后 3 行上下文」的模式，此时页头会显示「文件过大，仅显示改动区域」的提示

### 提交变更

在左侧栏顶部：

1. 勾选需要提交的文件（「已暂存」和「未暂存」两个分区的勾选都会计入）
2. 在输入框中填写提交说明
3. 点击 **提交**；或点击 **提交并推送**，提交后立即把当前分支推送到远程仓库

提交成功后，变更列表会清空，左侧提交历史会自动更新。

> **提交的是「勾选文件在工作区里的最新内容」**，而不是单纯提交暂存区：应用会先把未勾选路径的暂存条目重置，再对勾选的文件重新执行一次暂存，然后提交。因此即使某个文件在暂存之后又被改动过、没有重新暂存，它的最新改动也会一起进入提交，不需要额外操作。

### 冲突解决

当合并或变基操作产生冲突时，会自动进入冲突解决视图：

- **冲突文件列表**：列出所有存在冲突的文件
- **逐文件解决**：点击文件查看冲突详情
- **代码块对比**：显示每个冲突区域的几种版本：
  - 当前分支版本（ ours ）
  - 合并目标版本（ theirs ）
  - 合并后的版本（可以手动编辑）
- **分支选择**：点击 diff 顶部的分支名（当前分支 / 目标分支），可以一键选中该侧所有的冲突行，方便快速接受某一方的所有更改
- **接受选择**：可以选择接受当前分支版本、目标版本，或手动编辑后标记为已解决
- **批量解决**：支持逐个文件解决，或一键解决所有已编辑完成的文件

所有冲突解决后，应用会自动收尾完成操作：合并会生成合并提交，变基 / 优选（cherry-pick） / 还原（revert）会继续执行对应的 `--continue`。

## 6. 深色模式

点击页面右上角的 **主题切换按钮**（☀️ 或 🌙），可以在浅色模式和深色模式之间切换。

- **浅色模式**（☀️）：白色背景，适合白天或光线充足的环境
- **深色模式**（🌙）：深色背景，适合夜间或光线较暗的环境

主题偏好会自动保存，下次打开应用时自动恢复。

## 7. 中英文切换

点击页面右上角的 **语言切换按钮**：

- 当前为中文界面时，按钮显示 **EN**，点击后切换到英文
- 当前为英文界面时，按钮显示 **中**，点击后切换到中文

界面中的所有文字（包括按钮、标签、提示信息）会即时切换为对应的语言。语言偏好会自动保存，下次打开应用时自动恢复。
